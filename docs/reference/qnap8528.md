# qnap8528 driver — userspace interface reference

Source: <https://github.com/0xGiddi/qnap8528> at `457a965` (2026-10-11,
module v1.27), `src/qnap8528.c` and `src/qnap8528.h`. GPL-2.0-or-later.
The driver only *exposes* controls; it does no automatic fan control.

## Installation

```sh
apt install build-essential dkms linux-headers-$(uname -r)   # or proxmox-headers-*
git clone https://github.com/0xGiddi/qnap8528.git && cd qnap8528
make install            # dkms install .  (PACKAGE_VERSION=1.27, AUTOINSTALL=yes)
modprobe qnap8528 skip_hw_check=true    # TS-253D needs skip_hw_check
```

Persist: `/etc/modules-load.d/*.conf` → `qnap8528`;
`/etc/modprobe.d/*.conf` → `options qnap8528 skip_hw_check=true`.
(The plugin can manage both: System › QNAP › Drivers › "Load the qnap8528 module at boot".)

Loaded? `/sys/module/qnap8528` exists; a hwmon `name` equals `qnap8528`;
dmesg: "Hwmon device registered", "LED devices registered",
"Buttons input device registered", "device model is TS-253D".

## Module parameters (load time only; not visible in /sys/module/*/parameters)

| Param | Default | Meaning |
|-|-|-|
| `skip_hw_check` | false | Skip SuperIO chip-ID check (0x8528). Listed for ENE ECs (TS-453D, TS-464, TS-464EU, TR-464, Qu-X05). **The reference TS-253D (v1.24) logs `IT8528 EC device found successfully` without it** |
| `blink_sw_only` | false | Disable EC hardware blinking (and `blink_bicolor`) |
| `preserve_leds` | true | Keep LED state on unload |

Model detection: VPD `mainboard_model` / `backplane_model` strings from the
EC matched against `qnap8528_configs[]` (no DMI). No match → module load
fails with `-ENODEV`.

## hwmon (`/sys/class/hwmon/hwmonX`, `name` = `qnap8528`; X not fixed)

| Attribute | Mode | Notes |
|-|-|-|
| `fanN_input` | ro | RPM. From the model config (not probed). 65535 = junk/missing |
| `pwmN` | rw | **0–255**, stored as EC percent (`v*100/255`) → read-back drift (128→127). One `pwmN` per **group**; writing it sets all fans in the group |
| `tempN_input` | ro | m°C, whole-degree resolution. N = EC sensor index + 1; only sensors with 0 < raw < 128 at load time; later-invalid → `-ENODEV` |

No `pwmN_enable`, no min/target/alarm/label attributes, **no way back to
EC automatic mode** — every `pwmN` write forces manual (writes 0x10 to the
group mode register first).

PWM groups: 1 = fans 0–5, 2 = fans 6–7, 3 = fans 20–25, 4 = fans 30–35.

EC temperature numbering: 0–1 "CPU" (may be bogus on x86 — use coretemp),
5–7 system, 10–11 redundant PSU, 15–38 environment. On a TS-464 users saw
`temp1` chassis ≈38 °C, `temp6` backplane ≈31 °C, `temp11/12` = 2 °C (junk).

## LEDs (`/sys/class/leds/qnap8528::<name>`)

| LED | max | Values | HW blink window (`timer` delay) |
|-|-|-|-|
| `status` | 2 | 0 off, 1 green, 2 red | 470–790 ms (default 500/500 fits) |
| `status/blink_bicolor` | — | write-only; any value → green/red alternating; cancel by writing `brightness` | — |
| `usb` | 1 | 0 off, 1 on (blue) | 280–470 ms |
| `ident` | 1 | flashing locate; overrides disk LEDs | none |
| `jbod`, `10GbE` | 1 | on/off | none |
| `panel_brightness` | **100** | 0–100, dims all front LEDs | n/a |
| `hddN`, `ssdN`, `m2ssdN`, `u2ssdN` | 2 | 0 off, 1 green (present), 2 red (error) | 80–140 ms; 1+blink = activity, 2+blink = locate |

Set brightness (colour) **before** setting the `timer` trigger. Writing
`brightness=0` stops blinking. Delays outside the window → kernel software
blink. No per-disk activity blinking in the driver (see
`examples/qnap-disk-led-monitor.sh`).

## Input device (buttons)

`Name="qnap8528"`, `phys=qnap8528/input0`, polled every 100 ms from EC 0x143.

| Code | Source says | README says |
|-|-|-|
| `BTN_0` (256) | chassis open | chassis |
| `BTN_1` (257) | **USB Copy** | Reset |
| `BTN_2` (258) | **Reset** | USB Copy |

→ verify with `evtest`. Power button is ACPI (`KEY_POWER`, systemd-logind),
not this driver. Hold-time detection is up to userspace.

## Other sysfs (`/sys/devices/platform/qnap8528/`) — no trailing newline!

| Path | Mode | Values |
|-|-|-|
| `ec/fw_version` | ro | 8 chars |
| `ec/cpld_version` | ro | `0x..` |
| `ec/power_recovery` | rw | 0 stay off, 1 power on, 2 last state (`>2` → `-ERANGE`) |
| `ec/eup_mode` | rw | 0 off, 1 on; `-ENOTSUPP` (524) if EC lacks support |
| `vpd/enclosure_serial`, `vpd/enclosure_nickname` | ro | |
| `vpd/mainboard_{manufacturer,vendor,name,model,serial,date}` | ro | slow (5 ms/byte) |
| `vpd/backplane_*` | ro | `-ENOTSUPP` if no BP table |

## TS-253D config (`src/qnap8528.h:2271`, `"TS-253D", "Q05H0", "QY570"`)

- features: `pwr_recovery`, `eup_mode`, `led_brightness`, `led_status`,
  `led_usb`, `vpd_bp_table` (no jbod/ident/10GbE)
- fans `{1}` → `fan1_input`, `pwm1` (group 1)
- slots `hdd1`, `hdd2` with present/active/error/locate, HW blink
- reference unit: chip check passes without `skip_hw_check`; VPD `mainboard_model` = `70-0Q05H0201`, `backplane_model` = `70-1QY570111`, NUL padded to 32 bytes; EC fw `Q04WE018`; only `temp1` (≈21 °C idle) and `temp6` (≈25 °C) exist
- TS-251D (`Q04W1`) has an identical config

## Concurrency

EC access is serialised by a kernel mutex; a single transaction can block
up to ~5 s worst case. Keep polling modest and centralised (one daemon).

# qnap-qm2 (QM2 PCIe cards)

Source: <https://github.com/0xGiddi/qnap-qm2> at `880a920` (2026-09-26),
`src/qm2mod.c`. DKMS, module `qm2mod`, needs `i2c-algo-bit`; param
`preserve_leds` (default true). Independent of qnap8528. The driver does no
automatic fan control.

- Platform device `/sys/devices/platform/qm2.N/` (N = card index at load):
  `model`, `serial`, `pic_version` (ro, **with** trailing newline);
  `fan_default` (wo, only `1` accepted → PIC register 0x24 = 0, "restore
  factory fan control"; the author does not know whether that is
  temperature driven).
- hwmon `name` = `qm2`, parent = `qm2.N` (so `hwmonX/device` → `qm2.N`):
  - `temp1..2` (2-slot) / `temp1..4` (4-slot), m°C, whole degrees, **one
    per M.2 slot**, numbered like the slots (swap corrected).
  - `fan1_input`: PIC byte × 60 → RPM in 60 RPM steps.
  - `pwm1`: write 0–255 (clamped) to the PIC set-point; read returns the
    PIC's current duty register.
- LEDs `/sys/class/leds/qm2-<i2c adapter>:{red,green}:slot<N>`, parent
  `qm2.N`, max_brightness 2:
  - red: 0 off, 1 on, 2 **PIC blink**;
  - green: 0 off, 1 on, 2 on (no blink).
  - Standard triggers (`timer`, …) work (software blink).
- I2C adapter `i2c-<n>` (name `qm2-<prefix>-<domain>:<bus>`) has the PCIe
  switch as parent → NVMe SSDs on the card are below the same PCI path.
- Supported: QM2-2P10G1T(A/B), QM2-2P-344(A), QM2-2P-384(A), QM2-2P2G2T,
  QM2-2P410G1T/2T, QM2-2P-244A-A1, QM2-4P-384, generic 2P/4P (generic 2P
  cards have slots 1/2 swapped in hardware, corrected by the driver).
  **Not** QM2-2S10G1TB02 (PIC wired to the motherboard EC).
- Unlike qnap8528, a QM2 fan **can** be handed back (`fan_default`).
